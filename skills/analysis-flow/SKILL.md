# analysis-flow

데이터 분석 과정을 흐름도 한 장과 부록으로 만든다. 그림은 단계의 순서와
데이터 출처(DB · 서버 로그 · API · 파일)를 보여 준다. 부록은 단계마다 쿼리 ·
명령 전문을 싣는다. 그리기는 [`svg-diagram`](../svg-diagram/SKILL.md) 의
생성기 둘(`swimlane` · `boxflow`)이 한다. 이 스킬은 그 앞 단계를 맡는다:
단계를 모으고, 빈 칸을 묻고, 스펙을 쓴다.

예시: [examples/eqp-drift.steps.md](examples/eqp-drift.steps.md)(단계 표) →
[examples/eqp-drift.flow.json](examples/eqp-drift.flow.json)(`lane` 스펙) ·
[examples/eqp-drift-box.flow.json](examples/eqp-drift-box.flow.json)(`flow` 스펙).

## 입력

| 인자 | 모드 | 단계 표를 채우는 곳 |
| --- | --- | --- |
| 업무를 적은 글 | 설명 | 글에서 단계를 뽑는다. 빈 칸은 묻는다 |
| `지금까지`, 또는 인자 없음 + 세션에 분석 흔적 | 세션 정리 | 이 세션의 도구 호출에서 뽑는다 |
| `.json` 파일 | 스펙 | 스펙을 그대로 그린다(5단계부터) |
| 인자 없음 + 분석 흔적 없음 | 설명 | 무엇을 분석했는지 먼저 묻는다 |

분석 흔적은 다음 도구 호출이다: Bash 로 돌린 SQL(`psql` · `sqlite3` · `mysql` ·
`duckdb` 등), `curl` 같은 API 호출, `rg` · `awk` · `grep` 으로 읽은 로그, Read
나 `jq` 로 읽은 CSV · JSON, 그 결과로 한 계산.

옵션:

- `--shape lane`(기본): `swimlane`. 레인 = 출처 종류. 데이터가 어디서 왔는지가
  먼저 보인다.
- `--shape flow`: `boxflow`. 상자 안에 출처 · 쿼리 · 결과 세 줄. 단계 하나의
  내용이 먼저 보인다.
- `--style KEY`: svg-diagram 스타일. 이 스킬의 기본은 **`product`** 다.

## 단계 표

스펙 전에 만드는 중간물이다. 마크다운 표 한 장, 단계 하나에 한 줄.
파일 이름은 `<주제>.steps.md` 다.

| 칸 | 적는 것 |
| --- | --- |
| 번호 | 1부터. 그림 · 부록이 이 번호로 짝을 맞춘다 |
| 이름 | 단계 이름. 짧은 명사구 |
| 출처 | `종류: 이름`. 종류는 여섯 중 하나: DB 표 · 서버 로그 파일 · API · 파일 · 앞 단계 결과 · 사람 판단 |
| 쿼리 또는 명령 | 전문. 적는 법은 표 아래 |
| 조건 | 기간 · 필터 · 대상 |
| 얻은 것 | 표(행 수) · 수 · 판단. 한 줄 요약 |
| 다음 | 다음 단계 번호. 갈래면 `조건 → 번호 · 조건 → 번호`. 마지막 단계는 `끝` |

쿼리 또는 명령 칸은 줄마다 백틱으로 감싸고, 줄 사이에 `<br>` 을 넣는다. 글 안의
세로 막대(파이프)는 앞에 역슬래시를 붙인다. 표 칸이 이 막대로 나뉘기 때문이다.
예시 표의 3번 줄이 이 모양이다.

값이 없는 칸은 `—` 로 적는다. `—` 는 채운 칸이고, 아무것도 없는 칸만 빈 칸이다.

## 절차

1. **입력을 정한다.** 위 표에서 모드를 고른다.
2. **단계 표를 만든다.** 표 파일은 산출물 폴더에 둔다. 산출물 폴더는 사용자가
   정한 폴더이고, 정한 폴더가 없으면 scratchpad 다.
   - 설명 모드: 글에 나온 순서대로 단계를 적는다. 글에 없는 칸은 비워 둔다.
   - 세션 정리 모드: 도구 호출 순서대로 단계를 적는다. 쿼리 · 명령은 호출의
     전문을 그대로 옮긴다. 얻은 것은 결과를 한 줄로 줄인다. 같은 쿼리를 고쳐
     다시 돌렸으면 마지막 것 하나만 적는다. 계산은 출처를 `앞 단계 결과:
     N번` 으로 적는다.
3. **빈 칸을 묻는다.** 빈 칸만 묻는다. 한 번에 질문 하나, 선택지만 제시한다
   (추천 · 이유 없이).
   1. 순서: 단계 번호순, 단계 안에서는 출처 → 쿼리 또는 명령 → 조건 → 얻은 것 → 다음.
   2. 출처는 여섯 종류에서 고르게 하고, 이어서 이름(표 · 파일 경로 · URL)을 묻는다.
   3. 쿼리 · 명령은 붙여 넣어 달라고 한다. 없으면 `—` 로 받는다.
   4. 다 차면 표를 보여 주고 "이대로 그릴까요" 를 한 번 묻는다.
4. **스펙으로 옮긴다.** 스펙 파일 `<주제>.flow.json` 을 표 파일 옆에 쓴다. 두 모양
   공통 규칙:
   - 단계 하나 = 상자 하나. 상자 id 는 `s<번호>`, 상자 글은 `<번호>. <이름>`.
   - 그림에 싣는 쿼리 · 명령은 첫 줄 하나. 40자가 넘으면 40자에서 자르고 `…` 를
     붙인다. 이 줄은 고정폭 글꼴로 그린다.
   - 출처가 사람 판단이거나 다음 칸이 갈래인 단계는 `gate`, 다음 칸이 `끝` 인
     단계는 `io`.
   - 갈래는 선 `kind: "cond"` 에 다음 칸의 조건을 라벨로 단다.
   - `caption` 에 분석 한 줄 요약과 "번호는 부록과 짝" 을 적는다.

   `--shape lane`(`swimlane`):
   - 레인은 표에 나온 종류만, 이 순서로: DB · 서버 로그 · API · 파일 · 계산/판단 · 결과.
     id 는 `db` · `log` · `api` · `file` · `calc` · `result`.
   - 출처 → 레인: DB 표 → DB, 서버 로그 파일 → 서버 로그, API → API, 파일 → 파일,
     앞 단계 결과 · 사람 판단 → 계산/판단. 다음 칸이 `끝` 인 단계는 결과 레인.
   - `sub` = 쿼리 · 명령 첫 줄, `"code": true`. 쿼리 · 명령이 `—` 이면 `sub` 에
     얻은 것을 보통 글꼴로 적는다.

   `--shape flow`(`boxflow`):
   - 단계를 번호순으로 `col 0` 에 한 행씩 둔다. 한쪽 갈래에만 있는 단계는
     `col 1` 에, 두 갈래가 만나는 단계와 같은 행에 둔다.
   - `rows` = `["출처", "<종류> <이름>"]` · `["쿼리", "<첫 줄>", "code"]` ·
     `["결과", "<얻은 것>"]`. 키는 SQL 이면 `쿼리`, 그 밖은 `명령`.
     쿼리 · 명령이 `—` 이면 출처 · 결과 두 줄만 적는다.
5. **그린다.** 셋을 차례로 돌린다. `<svg-diagram>` 은 이 스킬 옆의
   `../svg-diagram` 폴더다.

   ```bash
   node "<svg-diagram>/gen.mjs" <주제>.flow.json --style product --html <주제>.flow.html
   node "<이 스킬 폴더>/appendix.mjs" <주제>.steps.md <주제>.flow.html
   node "<svg-diagram>/gen.mjs" <주제>.flow.json --style product --svg <주제>.flow.svg
   ```

   - `appendix.mjs` 가 미리보기 그림 아래에 부록을 붙인다. 단계 번호순으로 제목
     `<번호>. <이름>`, 출처 · 조건 · 얻은 것 한 줄씩, 쿼리 · 명령 전문 `<pre>`.
     다시 돌리면 부록을 바꿔 넣는다.
   - 미리보기를 열어 넘침 · 겹침 · 선이 상자를 지나는지 본다. 어긋나면 스펙의 칸
     배치나 글 길이를 고치고 다시 그린다.
   - 검사: `rg -n '<script|https?://|fill="#|style="' <주제>.flow.html` 이 0건이다.
6. **보고한다.** 스펙 · 단계 표 · HTML · SVG 경로, 단계 수, 물어서 채운 칸.

## 규칙

- 그림은 svg-diagram 의 철칙을 따른다: 좌표는 생성기가 내고, 스펙에는 구조만 적는다.
- 그림 종류는 `swimlane` · `boxflow` 둘이다. 둘로 그릴 수 없는 분석이면
  svg-diagram 철칙 3 대로 생성기부터 만든다.
- 쿼리 · 명령 전문은 단계 표와 부록에 둔다. 그림에는 첫 줄만 싣는다.
- 단계 표의 쿼리 · 명령 칸에는 세션에서 실제로 돌린 것이나 사용자가 준 것을
  적는다. 둘 다 없으면 묻는다.

## appendix.mjs

```bash
node appendix.mjs <단계표.md|단계표.json>                  # <style> + <section> 조각을 stdout 으로
node appendix.mjs <단계표.md|단계표.json> <미리보기.html>   # 미리보기에 넣는다
```

- 의존 0. script 0 · 외부 요청 0 · 인라인 색 0.
- JSON 입력은 단계 표의 칸 이름을 키로 쓰는 객체 배열이다. 쿼리의 줄 사이는 `\n`.
- 색 · 글꼴은 svg-diagram 스타일의 토큰(`--fg` · `--muted` · `--line` · `--box` ·
  `--font-mono` · `--fs-v`)을 쓴다. 스타일을 바꾸면 부록도 같이 바뀐다.
