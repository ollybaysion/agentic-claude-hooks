# html-doc

설계 문서나 분석 산출물을 **잘 쓴 블로그 글 같은 HTML 파일 하나**로 만든다.
겉모양은 이 폴더의 [template.html](template.html)(v3)이 정한다. 만든 뒤에는
[check.mjs](check.mjs) 가 철칙을 기계로 검사한다. 완성 예는
[examples/showcase.html](examples/showcase.html) 이다. AKG 설계 문서를 글로 다시 쓴 것이다.

모드는 넷이다. 요청을 보고 고른다.

| 모드 | 언제 | 글 |
| --- | --- | --- |
| 저작(기본) | 새 설계 문서 · 설명 글 · 결정 기록 | 원고를 새로 짧게 쓴다. 그림이 설명을 맡는다 |
| md 렌더 | "이 md 를 HTML 로" | 문장은 원본 그대로 둔다. 머리 규칙과 부품만 입힌다 |
| 범용 산출물 | 리포트 · 비교표 · 수치 페이지 | 필요한 부품만 쓴다. 철칙은 같다 |
| 시안 | "시안 만들어줘" · 배치 · 새 화면 · 새 UI 조각을 고를 때 | 안 여럿을 같은 장면으로 그린다. 고르는 것은 사용자다 |

## 철칙 (모든 모드)

1. **파일 하나가 전부다.** 브라우저가 열 때 가져오는 것은 0 개다. CDN 스크립트 ·
   웹폰트 · 이미지 파일 · CSS `@import` 는 `check.mjs` 가 막는다. 이미지는 `data:` URI,
   그림은 인라인 SVG 로 넣는다. `<a href="https://…">` 이동 링크는 리소스가 아니라 통과한다.
2. **script 0.** 차례는 정적 `nav`, 테마는 CSS 가 맡는다.
3. **머리는 넷이다.** 좌표 줄 → 제목(h1) → 부제 → 메타 한 줄. 본문은 첫 절에서 시작한다.
4. **차례는 어디서든 보인다.** 1100 px 이상은 왼쪽 고정 `nav.toc`, 아래는 머리 밑
   접이 `details.toc-m` 이다.
5. **글자 적게.** 한 절은 첫 문단 하나 + 목록 · 그림 · 상자로 짠다. 문단이 셋을 넘으면
   그림이나 상자로 바꿀 곳을 찾는다.
6. **시스템 글꼴 · 점선 0 · 라이트 + 다크.** 선은 실선이고 구분은 색 · 면이 맡는다.
   다크 토큰은 `@media (prefers-color-scheme: dark)` 와 `:root[data-theme="dark"]` 두 자리에
   같은 이름으로 둔다.
7. **글자 크기 폭을 크게.** 제목은 본문의 4 배 이상(72 px ÷ 17 px), 라벨은 11 ~ 12 px 다.
8. **색은 토큰으로.** 색 · 배경 · 테두리는 `var(--…)` 로만 쓴다. 토큰 · 부품 목록은
   [design.md](design.md) 에 있다.
9. **그림은 svg-diagram 이 그린다.** SVG 좌표는 생성기가 낸다. 그림 절을 따른다.
10. **언어.** 글은 쉬운 기술 한국어로 쓴다. 한 문장에 서술어 하나, 많아야 둘이다. 주어 +
    능동 동사로 쓴다. "~되어진다" 는 "~된다", "A 에 의해 고쳐진다" 는 "A 가 고친다" 로 바꾼다.
    하는 것만 적는다: 무엇을 어디서 하는지 쓴다. 코드 · 식별자 · `section id` 는 영어, id 는 `s1, s2, …` 순번이다.

시안 모드의 화면 틀(`.scr > .v`) 안은 앱 화면을 HTML · CSS 로 그린 것이다. 그 안은 철칙 5 · 9 대신
대상 앱의 꼴을 따르고, 철칙 6 · 8 대신 앱 토큰(`--a-…`, 라이트 고정)을 쓴다. 틀 밖 페이지는 철칙을
모두 지킨다([모드 — 시안](#모드--시안)).

## 머리 규칙

| 자리 | 마크업 | 무엇을 쓰나 |
| --- | --- | --- |
| 좌표 줄 | `nav.coord` | `path` = 대분류 › 중분류 › 이 문서. `rel` = 관련 문서(링크) |
| 제목 | `h1#top` | 주장 한 줄. "무엇을 한다" 꼴 |
| 부제 | `p.sub` | 문서 이름 · 종류 · 버전 |
| 메타 | `p.meta` | 날짜 · 읽는 시간(글자 수 ÷ 500 자/분, 올림) |

좌표를 만드는 순서:

1. md 앞머리(front matter)의 `where` 가 있으면 좌표 줄의 `path` 로 쓴다.
   `related` 는 `rel` 과 "다음에 읽을 글" 로 쓴다.
2. 앞머리가 없으면 레포 이름 › 폴더 이름 › 문서 종류로 스스로 만든다.
   예: `~/work/fdc-agent/AKG/docs/design.md` → `fdc-agent › AKG › 설계 문서`.
3. md 렌더 모드에서는 h1 의 ` — ` 앞을 제목, 뒤를 부제로 쓴다. ` — ` 가 없으면 부제는
   문서 이름 · 버전이다.

## 그림 — svg-diagram

무엇을 보이는지로 생성기 kind 를 고른다. 스타일은 늘 `doc` 이다. `doc` 은 이 문서의
토큰(`--ink · --line · --accent · --sans …`)을 읽어 라이트 · 다크가 같이 바뀐다.

| 보일 것 | kind |
| --- | --- |
| 무엇이 어느 칸에 있고 무엇과 이어지나 · 경계 틀(아키텍처) | `gridmap` |
| 상자 안에 키 · 값 줄이 있는 흐름 · 되돌아가는 선 | `boxflow` |
| 요청 하나가 참여자 사이를 오가는 순서 | `sequence` |
| 누가(레인) 하는지와 순서 | `swimlane` |
| 데이터가 본체 | 표(`.table-scroll`) |
| 그 밖(상태 그림 · 나무 그림 · 차트) | 생성기가 없으면 svg-diagram 철칙 3 대로 생성기부터 만든다 |

붙이는 순서:

1. 스펙 JSON 을 산출물 옆 `specs/` 에 쓴다. `id` 는 페이지 안에서 겹치지 않게 짓는다.
2. `<style>` 끝 `svg-diagram:` 주석 줄 아래에 CSS 를 한 번 넣는다.

   ```bash
   node "<svg-diagram 폴더>/gen.mjs" --css --style doc --solid
   ```

3. 그림마다 조각을 `figure > .panel` 안에 넣는다. `figcaption` 에 번호 배지와 한 줄 설명을 단다.

   ```bash
   node "<svg-diagram 폴더>/gen.mjs" specs/<그림>.json --style doc
   ```

`--solid` 는 점선 선언을 걷고 옅은 색으로 구분한다. 철칙 6 과 `check.mjs` 의 `no-dash` 가
이 출력을 기대한다.

## 공통 절차

1. `template.html` 을 출력 경로로 복사한다.
2. `<!-- CONTENT:START -->` 와 `<!-- CONTENT:END -->` 사이를 실제 내용으로 바꾼다.
   `<title>` 을 포함한 `{{…}}` 자리표시를 모두 채운다. `head` · CSS 는 그대로 둔다.
3. 차례 두 벌의 링크와 `section id` 를 맞춘다. 부품은 [design.md](design.md) 에서 복사한다.
   versus · triptych 를 쓰면 `patterns/` 견본의 `CSS:START … END` 를 `<style>` 끝에 붙인다.
4. 그림을 넣는다(그림 절).
5. 검사한다. exit 0 이 나올 때까지 고친다.

   ```bash
   node "<이 스킬 폴더>/check.mjs" <출력.html>            # 저작 · 범용 산출물
   node "<이 스킬 폴더>/check.mjs" <출력.html> --derived  # md 렌더
   node "<이 스킬 폴더>/check.mjs" <출력.html> --mockup   # 시안(2 판은 --min-opts 1)
   ```

6. 브라우저로 1400 px · 폰 390 px · 다크를 연다. 넘침 · 겹침을 눈으로 본다.
7. 파일 경로를 보고한다.

## 모드 — 저작(기본)

원고를 문제 → 접근 순서로 새로 쓴다. 절 뼈대:

1. **문제** — 누가, 어떤 상황에서, 무엇 때문에 곤란한가. 첫 문단(`.lead`) + 곤란한 점 목록.
2. **한 문장으로** — 접근을 한 문장으로 줄여 큰 인용 상자(`.pull`)에 둔다.
3. **전체 그림** — svg-diagram 그림 하나 + 짧은 목록 · 번호 흐름(`ol.flows`).
4. **구성 · 상태** — 필요한 만큼 그림과 코드 블록.
5. **정한 것** — 결정 카드(`ol.dec`). 카드 하나 = 제목 한 줄 + 까닭 한 줄.
6. **남은 것** — 체크 목록(`.note > ul.checks`). 정한 것은 `li.done`, 남은 것은 빈 칸.
7. **다음에 읽을 글** — `nav.next#next`. 좌표 줄 `rel` 과 같은 목록.

절은 내용에 맞게 줄이거나 합친다. 문서 자신이 원본이다. 끝은 다음에 읽을 글로 닫는다.

## 모드 — md 렌더

문장과 순서는 원본 그대로 옮긴다. 원본 md 가 원본이고 HTML 은 파생물이다.

- 짝: 앞머리 · h1 → 머리 넷(머리 규칙) / h2 → `section#sN > h2` / h3 → `h3` /
  코드 펜스 → `pre.code` / 표 → `.table-scroll > table` / 인용 → `.pull` 이나 `blockquote` /
  번호 목록 → `ol` / 인라인 코드 → `code`. 차례는 h2 목록에서 만든다.
- 출력 경로는 원본 옆 같은 이름이다: `docs/foo.md` → `docs/foo.html`.
- 문서 끝에 파생물 표기를 둔다(`--derived` 가 본다):

  ```html
  <footer class="derived" data-derived-from="<원본 상대 경로>">
    이 HTML 은 <code><원본 상대 경로></code> 에서 만든 파생물이다
    (<YYYY-MM-DD>, 원본 커밋 <git log -1 --format=%h -- 원본>). 내용은 원본 md 에서 고친다.
  </footer>
  ```

  원본이 git 레포 밖이면 커밋 자리에 그 사실을 적는다.
- 출력 경로에 파일이 있으면 연다. `data-derived-from` 이 있으면 덮어쓴다. 없으면 손으로
  만든 파일이라 사용자에게 묻는다.
- 원문에 `[그림]` 표시나 ASCII 그림이 있으면 svg-diagram 그림으로 바꾼다. 그림 안 글은
  원문 낱말을 쓴다.

## 모드 — 범용 산출물

리포트 · 비교 · 수치 페이지. 머리 넷과 차례는 같고, 부품은 필요한 것만 쓴다.

- 대표 수치 셋은 triptych 수치 타일(`h3.num`), 그 이상은 표로 보인다.
- 차트가 필요하면 세션에 `dataviz` 스킬이 있을 때 먼저 읽는다. 차트는 정적 인라인 SVG 로
  그리고 데이터 표를 같이 둔다.

## 모드 — 시안

**시안**은 구조가 다른 화면 안 여럿을 한 페이지에 나란히 놓은 것이다. 사용자가 그중에서 고른다.
페이지 틀은 [patterns/mockup.html](patterns/mockup.html) 이 복사 원본이다. 완성 예는
[examples/mockup.html](examples/mockup.html)(안 8 · 장면 2)이다.

### 시안 규칙

1. **시안은 여러 안이다.** 첫 판은 8 ~ 12 안을 그린다(적어도 8). 안 하나를 다듬는 것은 초안이다.
2. **갈림 축을 맨 위 한 줄로 적는다.** 축은 "이 안들이 무엇에 대한 것인가" 다. 축은 사용자 말에서
   가져온다(`data-axis-from="user"`). 만드는 쪽이 고른 축이면 "내가 고른 축" 이라고 적는다(`"author"`).
3. **레퍼런스가 먼저다.** 실제 제품의 같은 패턴을 찾는다. 안마다 "레퍼런스: 제품 — 링크 — 한 줄" 을
   붙인다. 제품에 없는 안은 "직접 지은 안" 이라고 적는다(`p.ref.own`).
4. **지금 코드에 있는 기능만으로 그린다.** 그리기 전에 화면의 값이 어디서 오는지 코드로 확인한다(파일 · 줄).
   새 기능이 있어야 그려지는 안은 그 안에 "X 기능이 있어야 한다(없음)" 라고 적는다(`p.need`).
   사용자가 지시한 새 기능은 "새로 생기는 것" 절에 한 번 모아 적는다.
5. **같은 장면 · 같은 예시 값.** 모든 안을 같은 장면 목록과 같은 값으로 그린다. 장면 위에 상태 축을
   한 줄로 둔다(`p.states`). 지어낸 값에는 "예시 값" 표시를 붙인다(`span.ex`).
6. **화면은 실제 px 로 그린다.** 앱 화면을 1440 × 900 실제 px 로 그린다. 틀이 화면을 줄인다.
   치수는 살아 있는 화면을 찍어 잰다. 장면을 누르면 100% 로 본다.
7. **겉모양도 안의 일부다.** 안마다 구조와 겉모양을 다르게 한다. 겉모양은 묻지 않고 여러 개 그린다.
   앱 화면 안은 그 앱의 토큰을 쓴다.
8. **점선 0 · 글자 크기 폭 크게.** 철칙 그대로다. 표시 제목과 안 번호는 본문의 4 ~ 6 배다(72 · 96 px ÷ 17 px).
9. **끝에 비교표와 레퍼런스 목록을 둔다.** 비교표의 열은 축에서 나온다. 예: 손동작 수 · 새 기능 필요 여부 ·
   긴 목록 처리.
10. **고르는 것은 사용자다.** 추천은 페이지에 적지 않는다. 끝 보고에 한 줄만 적는다.
11. **고른 뒤에는 합친다.** 사용자가 기준 안을 고르면 다른 안의 장점을 넣을 자리를 적는다(무엇을 · 어느 안에서 ·
    어느 자리로). 합친 안은 같은 페이지 맨 앞에 2 판으로 더한다. 기준 안의 눈에 띄는 요소 하나는 그대로 살린다.
    2 판은 안 수 하한을 두지 않는다(`--min-opts 1`).
12. **디자인 요청은 뒤 판까지 간다.** 사용자가 한 번 말한 디자인 요청은 그 화면의 뒤 판 전부에 적용한다.
13. **넘길 때는 브리핑을 쓴다.** 시안을 다른 agent 에 넘길 때 아래 "브리핑에 적을 것" 을 채운다.

### 페이지 구성

| 자리 | 마크업 | 무엇을 쓰나 |
| --- | --- | --- |
| 머리 넷 + 축 줄 | `header` 안 `p.axis[data-axis-from]` | 철칙 3 의 머리 넷. 메타 밑에 축 한 줄 |
| 차례 | `nav.toc` · `details.toc-m` | 고정 절 + 안 목록. 안 번호를 `.no` 에 쓴다 |
| 새로 생기는 것 | `section > .newbox` | 사용자가 지시한 새 기능. 모든 안이 전제한다 |
| 장면과 예시 값 | `dl.scenes` · `span.ex` | 장면 목록 · 예시 값 · 셈 규칙 |
| 지금 화면 | `.shots.one > figure.shot` | 지금 코드의 화면 한 장. 값의 출처(파일 · 줄) |
| 안 | `section.opt#oN` | 큰 번호 · 이름 · 한 줄 설명 · `p.ref` · `p.need` · `p.states` · 장면 줄 |
| 비교표 | `.table-scroll > table.cmp` | 맨 위 줄이 지금 화면이다. 안 이름은 `#oN` 링크 |
| 레퍼런스 | `ol.refs` | 안마다 기댄 제품 화면. 링크 · 안 번호 · 한 줄 |

### 화면 틀

장면 하나는 `figure.shot#oN-sK > div.scr#oN-sK-z > div.v` 다. `.v` 안에 앱 화면을 1440 × 900 px 로 그린다.

- **줄이기.** `.scr` 는 `container-type: inline-size` 다. `.v` 는
  `transform: scale(tan(atan2(100cqw, 1440px)))` 로 틀 폭에 맞춰 준다. `tan(atan2(길이, 길이))` 는
  길이 ÷ 길이를 수로 바꾼다. script 는 쓰지 않는다.
- **100% 보기.** `a.zopen` 은 `href="#oN-sK-z"` 로 틀을 `:target` 으로 만든다. 틀이 화면을 덮고 1440 × 900
  그대로 스크롤된다. `a.zclose` 는 `href="#oN-sK"` 로 figure 에 돌아간다.
- **앱 토큰.** 앱 색은 `:root` 의 `--a-…` 블록 하나에 둔다. 다크 자리에는 다시 정하지 않는다. 그래서 틀 안은
  다크에서도 라이트다. 틀 안 인라인 `style` 은 `var(--a-…)` 만 쓴다. 앱 화면에는 `h1` 을 쓰지 않는다.
- **표지.** `i.mk` 는 손동작 순서의 원 숫자, `.hl` 은 손이 닿는 자리 · 바뀐 자리의 테다. 색은 앱 토큰
  `--a-mark` 다.

### 절차

1. 사용자 말에서 축을 뽑는다. 축이 없으면 축을 하나 고르고 "내가 고른 축" 으로 적는다.
2. 그 화면의 코드를 읽는다. 값마다 파일 · 줄을 적는다. 새 기능이 필요한 자리를 표시한다.
3. 살아 있는 앱을 headless Chrome 1440 × 900 으로 찍는다. 치수와 토큰을 잰다.
4. 레퍼런스를 찾는다. 안마다 제품 · 링크 · 한 줄을 정한다.
5. 장면 목록과 예시 값을 정한다.
6. `template.html` 을 복사한다. `patterns/mockup.html` 의 `mockup 패턴 CSS` 와 `앱 화면 CSS` 블록을
   `<style>` 끝에 붙인다. 앱 화면 CSS 는 대상 앱의 토큰 · class 로 바꾼다.
7. 정적 HTML 을 찍어 낸다(아래). 결과를 CONTENT 자리에 넣는다.
8. 검사한다: `check.mjs <출력.html> --mockup`. 2 판만 있는 페이지는 `--min-opts 1` 을 더한다.
9. 브라우저로 1400 px · 390 px · 다크를 연다. 장면 하나를 눌러 100% 와 닫기를 본다.
10. 끝 보고를 쓴다(링크 · 안마다 한 줄 · 추천 하나 · 잰 치수 · 정한 것 · 미확인).

### 정적 HTML 찍어 내기

안 11 × 장면 10 이면 화면이 110 장이다. 손으로 쓰지 않는다. 만드는 쪽이 scratchpad 에 작은 Node 생성
스크립트를 쓴다. 스크립트의 출력은 정적 HTML 이다. 산출물에는 script 가 들어가지 않는다.

1. **데이터.** 예시 값 배열(목록 · 이름 · 표 이름)과 장면 상태(`S1: { 고른 것: [], … }`)를 둔다.
2. **껍데기 함수.** 앱의 고정 부분(레일 · 머리 · 패널 · 입력창)을 함수 하나씩으로 쓴다.
3. **안.** 안 하나 = `{ no, name, one, ref, need, scenes: { S1: (s) => html, … } }`. 안마다 바뀌는 부분만 그린다.
4. **틀.** `figure.shot` · `.scr` · `.v` · 여는 · 닫는 링크를 내는 함수 하나가 모든 장면을 감싼다.
5. **출력.** `node gen.mjs > content.html` 로 찍고 CONTENT 자리에 넣는다. 고칠 때는 스크립트를 고쳐 다시 찍는다.

이미 script 로 그린 옛 시안은 headless Chrome `--dump-dom` 으로 한 번 렌더한다. 그 결과에서 `.v` 안을
떼어 새 틀에 옮긴다. 스킬은 범용 생성기를 두지 않는다. 화면마다 그리는 코드가 다르다.

### 브리핑에 적을 것

시안을 다른 agent 에 넘길 때 브리핑에 아래를 적는다.

- 사용자 말 원문(시각 포함)
- 축 한 줄과 축의 출처
- 코드 사실: 화면의 값이 오는 파일 · 줄
- 전제하는 새 기능("새로 생기는 것")
- 장면 목록과 예시 값
- 잰 치수 · 앱 토큰을 잴 곳(워크트리 · 포트)
- 2 판이면 기준 안과 가져올 것(무엇을 · 어느 안에서 · 어느 자리로)
- 끝 보고 항목: 링크 · 안마다 한 줄 · 추천 하나 · 잰 치수 · 정한 것 · 미확인

## Artifact 퍼블리시 (옵션)

로컬 파일이 기본이다. Artifact 도구가 세션에 있고 사용자가 공유 URL 을 원할 때만
(`--artifact` 또는 말로 요청) 더 올린다.

1. `artifact-design` 스킬을 먼저 읽는다.
2. 껍데기를 벗긴 사본을 scratchpad 에 만든다. `<!DOCTYPE html>` · `<html>` · `<head>` ·
   `<body>` 태그와 `meta` 를 걷는다. `<title>` 은 Artifact `title` 로 옮긴다. `<style>` 은
   본문 맨 위로 내린다. 테마 선택자와 자기완결은 그대로 계약을 맞춘다.
3. 원본 로컬 파일은 그대로 둔다.
