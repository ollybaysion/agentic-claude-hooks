지금 무엇이 곤란한가

에이전트는 프롬프트에 맞는 지식 문서를 받아서 답한다. 그 문서는 지금 claude-hooks 레포 안에 md 로 있다.

곤란한 점은 셋이다.

  • 혼자만 고친다. 문서는 한 사람의 로컬에 있다. 다른 사람은 보지도 고치지도 못한다.
  • "맞다"의 표시가 약하다. 확인 안 된 문장은 앞에 추정) 을 붙인다. 글자 하나가 틀리면 표시가 사라진다.
  • 한글 키워드는 안 걸린다. 키워드 토크나이저가 영문 · 숫자만 읽는다.

한 문장으로

지식을 쓰고 · 검토하고 · 승격하는 일은 새 서버로 옮긴다. 에이전트에게 지식을 넣는 일(주입)은 claude-hooks 에 남긴다.

문서의 원본은 JSON 이다. md 는 JSON 에서 찍어 낸 사본이다.

render(json) === md

전체 그림

  • 서버: store/(git 레포, 서버만 쓴다) · users.json(토큰 해시, git 밖 유일한 상태) · REST API + 대시보드.
  • 로컬: akg CLI(sync · propose · catalog-push) · 미러 ~/.claude/akg/ · keyword-docs 프로바이더.
  • 프로바이더 A 모드 = 미러 md 를 넣는다. B 모드 = 서버에서 새 본을 당긴다. 실패하면 미러로 돌아간다.

흐름은 셋이다.

  1. 읽기. 키워드는 늘 로컬 미러에서 찾는다. 서버가 죽어도 마지막 미러로 돈다.
  2. 쓰기. 사람은 대시보드에서 고친다. 에이전트는 제안(proposal)을 보낸다. 모든 변경은 서버 API 한 곳을 지난다.
  3. 승격. 검토 대기열에서 슬롯 하나씩 채택하고 승격한다.

지식 하나는 무엇으로 되어 있나

  • 문서 = 관리 단위. 테이블 하나 · 커맨드 하나 · 용어 하나.
  • 팩트 = 기계 지식. DB · 코드와 대조하면 참 · 거짓이 나온다. 등급이 없다.
  • 슬롯 = 사람 지식의 자리. 사람이 검토해야 맞다고 한다. 등급은 슬롯에만 있다.

scaffold → inferred → confirmed. confirmed 로 가는 길은 승격(promote) 하나다. deprecated 는 신뢰를 거둔 상태다. 되살리면 inferred 로 간다.

{ "text": "센서 사용 여부('Y'=활성)",
  "tier": "inferred",
  "evidence": ["fdc-app/src/schema-map.ts:72"],
  "by": "agent:propose-codebase",
  "at": "2026-07-17T05:00:00Z" }

정한 것 일곱

  1. 코퍼스는 옮기고, 주입기는 남긴다. claude-hooks 는 한 줄도 안 고친다. 설정 넉 줄로 미러를 가리킨다.
  2. 저장소는 git 레포가 전부다. 운영 DB 가 없다. 변경 하나 = 커밋 하나. 쓰기 큐가 하나라 머지 충돌이 없다.
  3. 원본은 타입별 JSON 이다. 모르는 키는 거부한다. md 는 렌더 결과다.
  4. 신뢰 등급은 필드다. 추정) 접두사 대신 tier 칸을 쓴다.
  5. 키워드는 문서가 가진다. 인덱스는 서버가 쓰기 때 다시 만든다.
  6. 승격은 사람만 한다. 역할은 viewer · editor · approver 셋이다. 에이전트 토큰에는 승격 권한이 없다. 토큰이 없으면 서버가 뜨지 않는다.
  7. 서버는 새로 만든다. 관측 서버를 키우지 않는다. Fastify 하나, DB 없음.

아직 정하지 않은 것

  • 정함레포 이름 = agent-knowledge-governance(akg).
  • 정함domain-skill 스펙 v2 는 akg 가 낸다. 남은 것은 시점이다.
  • 호스팅: 사내 서버 사양 · HTTPS 프록시 · SSO 유무.
  • 범용 keyword-docs 를 서버에 넣을지, 로컬에 둘지.
  • 관측 대시보드의 문서 탭을 언제 걷을지.
  • 옛 문서의 ## 마이그레이션 주의 내용을 옮길지 버릴지.
  • 주입 기본 모드를 A 로 할지 B 로 할지. B 의 타임아웃 400 ms 가 맞는지.
  • 확인된(confirmed) 문서만 넣는 것을 기본으로 할지.
